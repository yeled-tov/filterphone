# FilterPhone

סינון אינטרנט לכל הטלפון: **VPN** (WireGuard) + **סינון DNS** (AdGuard Home) + **סינון תמונות בצד השרת** (SigLIP2 + NudeNet + סגמנטציה), עם אפליקציה אחת ב-Flutter, הרשמה עם אישור מנהל, וחסימות בלחיצה לכל מכשיר.

```
טלפון (אפליקציית FilterPhone + "מגן FilterPhone")
  │  WireGuard — כל התעבורה, IPv4 ו-IPv6
  ▼
שרת (Oracle, ירושלים)
  ├─ DNS ──────────────▶ AdGuard Home: חסימת אתרים, חיפוש בטוח, עקיפות
  │                         + כללים לכל מכשיר ($client=) שה-API מסנכרן
  ├─ HTTP/HTTPS ───────▶ fp-proxy (mitmproxy שקוף)
  │                         │  אתר חסום למכשיר → דף "האתר חסום"; תמונות נאספות; השאר זורם
  │                         ▼
  │                      fp-engine: hash → קאש (Redis) → SigLIP2 + ראשים → [NudeNet] → [סגמנטציה] → החלטה
  └─ api.filterphone.com ▶ Caddy (HTTPS) → fp-api: הרשמה ובקשות, מדיניות לכל מכשיר, ממשק ניהול
```

## רמות סינון

| רמה | שם | מה נחסם |
|---|---|---|
| 0 | כבוי | שום תמונה לא נבדקת (חסימות האתרים והאפליקציות שהמנהל בחר — עדיין חלות) |
| 1 | מחמיר | כל תמונה של אישה/ילדה, גם בלבוש צנוע. גבר, נוף, מוצר — עובר. תמונה שאי אפשר לבדוק — נחסמת |
| 2 | בינוני | לבוש צנוע עובר. עור חשוף נצבע בשחור **לפי צורת הגוף** (סגמנטציה), ובלבוש חשוף מאוד — כל הגוף חוץ מהפנים. עירום נחסם. תקלה במנוע — חסימה |
| 3 | בסיסי | רק עירום מפורש |

רק המנהל משנה רמה. הלקוח יכול לבקש שינוי מהאפליקציה, והבקשה מגיעה לממשק.

## לקוח חדש — מהרשמה עד חיבור

1. הלקוח מתקין את האפליקציה ובוחר **"הרשמה"**: שם, טלפון, אימייל, שם המכשיר → רמת סינון → חסימות נוספות ("הכי מבוקשים" מסומנים למעלה, ואחריהם הכול לפי נושא) → הערה חופשית → שליחה.
2. הבקשה מופיעה בממשק תחת **"בקשות"** (עם מונה). שם רואים את הפרטים, מה ביקש, ומחליטים: רמה, חסימות, רשימות אישיות, הערת תשלום / "משולם עד".
3. **"אישור ופתיחה"** — השרת מקצה כתובת VPN ומפתח, והטלפון (שבודק כל 20 שניות) מתחבר לבד. דחייה — עם הסבר שהלקוח רואה.
4. אחר כך הלקוח יכול לשלוח **"בקשת שינוי"** מהאפליקציה; היא מגיעה שוב ל"בקשות".

עדיין אפשר גם בדרך הישנה: "קודי הפעלה" ← צור קוד ← הלקוח בוחר "יש לי קוד הפעלה".

## חסימות בלחיצה (לכל מכשיר)

בעמוד המכשיר: 45 אפשרויות ב-12 נושאים, כל אחת מתג. השינוי נשמר מיד וחל תוך שניות. כל אפשרות משתמשת בכל השכבות שרלוונטיות לה:

| שכבה | איך | מתי זה עובד |
|---|---|---|
| **DNS** (AdGuard) | כלל `‎||host^$client=<IP של המכשיר>` שה-API מסנכרן | כל אפליקציה ודפדפן, כולל שיחות |
| **פרוקסי** | חסימה לפי SNI / Host, דף "האתר חסום" בעברית, כללי כתובת (למשל לשונית "תמונות" בגוגל), בלי תמונות, בלי וידאו | תמיד, גם בלי AdGuard |
| **מגן FilterPhone** בטלפון | שירות נגישות: אפליקציה חסומה → מסך הבית; מסך חסום (צפייה בסטטוס) → "אחורה". במנהל מכשיר — האפליקציה מוסתרת | אחרי שהלקוח מפעיל את המגן (האפליקציה מראה איך). הממשק מראה אם הוא פעיל |

דוגמאות: תמונות פרופיל בוואטסאפ (`pps.whatsapp.net`), סטטוסים (מגן), חנות Play (DNS + מגן), Chrome / כל הדפדפנים (מגן), הפיד של גוגל, חיפוש תמונות, רשתות חברתיות, אליאקספרס/טמו/שיין, אתרי APK ואפליקציות VPN. בנוסף: **כל אפליקציה** מרשימת האפליקציות שהטלפון מדווח, רשימת אתרים אישית לחסימה, רשימת אתרים מותרים, ו"תמונות באפליקציות" (חסום / מותר / לפי הרמה).

### AdGuard
ההתקנה (`install.sh`) יוצרת ב-AdGuard משתמש נפרד בשם `filterphone-api` עם סיסמה אקראית, ושומרת אותה ב-`/etc/filterphone/filterphone.env` — אין צורך לעשות כלום. המשתמש שלכם בממשק של AdGuard לא משתנה. ב"מערכת" בממשק הניהול רואים אם הסנכרון עובד. הכללים נכתבים בתוך בלוק מסומן ב-"Custom filtering rules" — כללים שכתבתם ידנית לא נגעים.

## הפעלה

### שרת
```bash
deploy/deploy.sh
```
מעלה את `server/`, `tools/` ו-`deploy/` לשרת ומריץ `install.sh`. הסקריפט בטוח להרצה חוזרת, ומגבה לפני כל שינוי ל-`/root/fp-backups/<תאריך>` — כולל מסד הנתונים. הגרסה שרצה קודם נשמרת ב-`/opt/filterphone/src.prev`. מסד הנתונים מתעדכן לבד (גרסה 1: לקוחות, בקשות, מדיניות לכל מכשיר, יומן פעולות), ו-AdGuard מתחבר לבד (משתמש API נפרד; המשתמש שלכם לא משתנה).

- **העלאה מ-GitHub, בלי המחשב** (אחרי הגדרה חד-פעמית — [DEPLOY_PROMPT.md](docs/DEPLOY_PROMPT.md) שלב 6): GitHub → Actions → "העלאה לשרת" → Run, ובוחרים both / server / apk / status / rollback. המפתח של GitHub מוגבל בשרת לפקודות של `deploy/ci_deploy.sh` בלבד.
- **חזרה לגרסה הקודמת** (עדכון שלא הצליח): `sudo bash /opt/filterphone/src/deploy/rollback_version.sh /root/fp-backups/<תאריך>`
- **חזרה למערכת הישנה** (של לפני 5.10.2026): `sudo bash /opt/filterphone/src/deploy/rollback.sh /root/fp-backups/<תאריך>`

מנהל ראשון (פעם אחת, בשרת):
```bash
sudo -u filterphone /opt/filterphone/venv/bin/python -m filterphone.api.cli set-admin admin
```

### אפליקציה
כל דחיפה ל-`app/` בונה ב-GitHub Actions קובץ APK חתום (Artifacts → `FilterPhone-APK`). לפרסום לדף ההורדה:
```bash
deploy/publish_apk.sh
```
הלקוחות מורידים מ-`https://api.filterphone.com/download/`.

### ראשי הסיווג
GitHub → Actions → "אימון ראשי סיווג" → Run. האימון שומר `heads.json` ודוח דיוק במאגר; אחר כך `deploy/deploy.sh`.

## בדיקות ותקלות

בשרת:
```bash
systemctl status fp-engine fp-proxy fp-api caddy adguardhome
journalctl -u fp-engine -n 50     # סיכום כל 5 דקות: כמה תמונות, כמה מהקאש, כמה נחסמו
journalctl -u fp-proxy -n 50
journalctl -u fp-api -n 50        # סנכרון WireGuard / AdGuard
```

```bash
pip install -e "server[dev]" && pytest server/tests                 # 98 בדיקות
cd app && flutter analyze && flutter test                           # האפליקציה
python tools/dev_admin.py     # ממשק הניהול עם נתוני דוגמה: http://127.0.0.1:8099/admin (admin / demo-password)
```

## מגבלות שחשוב להכיר

- **אנדרואיד 7+:** רוב האפליקציות לא סומכות על תעודה שהמשתמש התקין, ולכן סינון התמונות חל על **Chrome** ודפדפנים דומים. באפליקציות אחרות: ברמות 1–2 שרתי התמונות שלהן לא נפתחים (התמונות לא נטענות), ברמה 3 הן עוברות. אפשר לשנות לכל מכשיר ("תמונות באפליקציות").
- **מגן FilterPhone** פועל רק אחרי שהלקוח מפעיל אותו בהגדרות הנגישות, ובאנדרואיד 13+ (התקנה שלא מהחנות) צריך קודם "התרת הגדרות מוגבלות". הלקוח יכול לכבות אותו — הממשק מראה זאת. נעילה מלאה = מנהל מכשיר (השלב הבא).
- **סטטוסים בוואטסאפ:** המגן חוסם את מסך הצפייה. התמונות הקטנות ברשימת העדכונים מוצפנות ואי אפשר לסנן אותן — כדי להעלים גם אותן בוחרים "מדיה בוואטסאפ".
- **טלגרם, משחקים, דפדפנים** — מתחברים לכתובות IP ישירות או נראים כמו אתר רגיל, ולכן החסימה שלהם בעיקר דרך המגן.
- **אייפון:** דורש חשבון Apple Developer בתשלום (Network Extension) ובנייה על macOS.
- **רישיונות:** SigLIP2 — Apache-2.0. ‏MediaPipe Selfie Multiclass — Apache-2.0. ‏WireGuard — Apache-2.0 / GPL-2.0. ‏**NudeNet — AGPL-3.0**: בשימוש כשירות רשת כדאי לבדוק משפטית, או להחליף בעתיד בגלאי ברישיון מתירני.
