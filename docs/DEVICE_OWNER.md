# מנהל מכשיר (Device Owner) — הקמה, מה נאכף, ומה אנדרואיד לא מאפשר

המסמך הזה מסביר את שלוש רמות הניהול של טלפון עם FilterPhone, איך מקימים טלפון מנוהל
(QR / adb), מה בדיוק נאכף, איך עובדים עדכונים, ומה **לא** אפשרי באנדרואיד — בלי הגזמות.

> נבדק: בנייה, בדיקות יחידה, lint ובדיקת ה-APK (הרשאות ורכיבים). **לא** נבדק כאן על טלפון
> אמיתי — לפני לקוחות צריך לעבור את רשימת הבדיקה שבסוף על 2–3 טלפונים (Pixel, Samsung, Xiaomi).

---

## 1. שלוש רמות ניהול

| | בלי ניהול | מנהל מכשיר רגיל (Device Admin) | **Device Owner** (מכשיר מנוהל במלואו) |
|---|---|---|---|
| איך מפעילים | מתקינים את האפליקציה | כפתור באפליקציה ← אישור בחלון של אנדרואיד | **רק בטלפון מאופס**: QR / adb / zero-touch |
| מי אוכף | הסינון בשרת + המגן (נגישות) | כמו בלי ניהול | **אנדרואיד עצמו** (DevicePolicyManager) |
| הסרת FilterPhone | אפשרית (הממשק מראה "אדום" כשהדיווח נפסק) | צריך קודם לבטל את מנהל המכשיר — השרת מקבל דיווח | **חסומה** |
| כיבוי ה-VPN | אפשרי — מדווח, אדום בממשק | אפשרי — מדווח | **חסום**: VPN תמיד מופעל + חסימת חיבורים בלי VPN |
| איפוס יצרן מההגדרות | אפשרי | אפשרי | **חסום** |
| איפוס ממצב שחזור (recovery) | אפשרי | אפשרי | **אפשרי** — אנדרואיד לא מאפשר לאף אפליקציה למנוע אותו (ראו FRP) |
| ביטול הניהול | — | המשתמש מבטל בהגדרות | רק איפוס יצרן |

**מנהל מכשיר רגיל** הוא API ישן: גוגל הוציאה ממנו את רוב היכולות (מאנדרואיד 9–10), והמשתמש
יכול לבטל אותו בכל רגע. ב-FilterPhone הוא רק מוסיף "חיכוך" להסרה ודיווח לשרת כשמבטלים —
הוא **לא** מונע שום דבר באמת, והממשק מציג אותו ככזה.

**Device Owner** הוא הדרך הרשמית של Android Enterprise לטלפון מנוהל. כל מה שמופיע בטבלה
למטה נאכף ע"י אנדרואיד, בלי נגישות ובלי "טריקים".

## 2. מה Device Owner מחיל

בממשק הניהול: מכשיר ← כרטיס "מנהל מכשיר (Device Owner)". כל שורה מסומנת לכל מכשיר "הוחל" /
"נכשל בטלפון" לפי מה שהטלפון דיווח (שום כישלון לא מוסתר).

| הגדרה | ברירת מחדל | מה אנדרואיד עושה |
|---|---|---|
| `block_uninstall` | פעיל | אי אפשר להסיר את FilterPhone |
| `always_on_vpn` | פעיל | VPN תמיד מופעל **+ lockdown**: בלי המנהרה אין אינטרנט בכלל (FilterPhone עצמה פטורה, כדי שתוכל להתחבר). מוחל רק אחרי שיש הגדרות VPN — עד אז "ממתין" |
| `disallow_config_vpn` | פעיל | אי אפשר לשנות הגדרות VPN / להפעיל VPN אחר |
| `disallow_factory_reset` | פעיל | איפוס יצרן **מתוך ההגדרות** חסום (לא מצב שחזור!) |
| `disallow_safe_boot` | פעיל | אין "מצב בטוח" (שעוקף אפליקציות) |
| `disallow_add_user` | פעיל | אין משתמש / אורח נוסף (שבו אין סינון) |
| `disallow_unknown_sources` | פעיל | אי אפשר להתקין קובצי APK (FilterPhone מתעדכנת לבד — סעיף 5) |
| `disallow_private_dns` | פעיל | אי אפשר להגדיר DNS פרטי; DNS פרטי שכבר הוגדר מוחזר ל"אוטומטי" |
| `disallow_debugging` | כבוי | חוסם ADB ואפשרויות מפתחים. כבוי כברירת מחדל כדי שאפשר יהיה לתקן; מומלץ להפעיל אחרי שהטלפון עובד |
| `disallow_install_apps` | כבוי | אי אפשר להתקין אפליקציות בכלל (גם מהחנות) |
| `disallow_modify_accounts` | כבוי | אי אפשר להוסיף / להסיר חשבונות |
| `hide_blocked_apps` | פעיל | אפליקציה שנחסמה בטלפון **מוסתרת** (setApplicationHidden) — בלי צורך בנגישות |
| `frp_accounts` | ריק | מזהי חשבונות Google לשחרור אחרי איפוס (סעיף 6) |
| `lock_task_packages` | ריק | אפליקציות שמותר להן מצב קיוסק |

בנוסף, במנהל מכשיר: תעודת הסינון מותקנת בלי חלון (installCaCert), והרשאת ההתראות (אנדרואיד 13+)
ניתנת אוטומטית.

**מה גם Device Owner לא יכול:** להפעיל את שירות הנגישות (רק המשתמש יכול — אנדרואיד לא נותן לאף
אפליקציה להדליק נגישות). לכן מגן הנגישות עדיין צריך הפעלה ידנית אם רוצים חסימת **מסכים**
(סטטוס בוואטסאפ) ותמונות פרופיל. חסימת **אפליקציות** במנהל מכשיר עובדת גם בלעדיו (הסתרה).

## 3. הקמה ב-QR (הדרך המומלצת)

### הכנה חד-פעמית בשרת
1. קובץ האפליקציה מפורסם בדף ההורדה (`FilterPhone-universal.apk`): GitHub ← Actions ←
   "העלאה לשרת" ← `apk` (או `deploy/publish_apk.sh`).
2. מומלץ: טביעת תעודת החתימה, כדי שהטלפון יוודא גם את החותם ולא רק את הקובץ:
   ```
   # מתוך הלוג של הבנייה ב-GitHub (שלב "אימות חתימה": certificate SHA-256 digest), או:
   apksigner verify --print-certs FilterPhone-universal.apk | grep 'SHA-256'
   # ואז בשרת, ב-/etc/filterphone/filterphone.env:
   FP_APK_SIGNATURE_SHA256=<64 תווי hex>
   sudo systemctl restart fp-api
   ```

### בממשק הניהול
"קודים" ← "הקמת מכשיר מנוהל ב-QR": רמה, שם הלקוח, ו-Wi-Fi (לא חובה) ← "צור QR".
ה-QR מכיל קוד הפעלה חד-פעמי (ואם הוזנה — סיסמת Wi-Fi), ולכן **לא שולחים אותו בקבוצות**.
ה-QR מאמת את קובץ ה-APK שהיה בדף ההורדה כשנוצר — אחרי פרסום גרסה חדשה יוצרים QR חדש.

### בטלפון
1. טלפון **מאופס להגדרות יצרן** (חדש, או אחרי איפוס). **לא** מוסיפים חשבון Google לפני ההקמה.
2. במסך הפתיחה הראשון: **6 הקשות באותו מקום** ← נפתח סורק QR.
   (אנדרואיד 9 ומעלה — סורק מובנה. אנדרואיד 8 — מבקש קודם Wi-Fi ומוריד סורק. FilterPhone דורשת אנדרואיד 8 ומעלה.)
3. סורקים. הטלפון מתחבר ל-Wi-Fi, מוריד את FilterPhone, **מאמת את הטביעה**, מתקין ומגדיר אותה
   כמנהלת המכשיר. בזרימה החדשה (חובה מאנדרואיד 12) FilterPhone עונה "מכשיר מנוהל במלואו"
   (GET_PROVISIONING_MODE) ומחילה את הגדרות הבסיס בסוף ההקמה (ADMIN_POLICY_COMPLIANCE); בזרימה
   הישנה (אנדרואיד 8–11) — באירוע סיום ההקמה (PROFILE_PROVISIONING_COMPLETE). שתיהן נתמכות.
4. ממשיכים את אשף ההקמה. בסיום פותחים את FilterPhone: היא **מתחברת לבד** עם הקוד שבתוך ה-QR,
   מקבלת הגדרות VPN, ומיד אחר כך נועלת "VPN תמיד מופעל". אם מתבקש — מאשרים חיבור VPN.
5. (לא חובה) מפעילים את "מגן FilterPhone" בהגדרות הנגישות — לחסימת מסכים ותמונות פרופיל.
6. בממשק: המכשיר מופיע ירוק, עם "מנהל מכשיר: כן" וכל שורות כרטיס Device Owner "הוחל".

**מגבלה:** QR provisioning הוא חלק מאשף ההקמה של גוגל. בטלפונים בלי שירותי Google (למשל דגמי
Huawei חדשים) או עם אשף מותאם של יצרן — ייתכן שאין 6 הקשות; אז משתמשים ב-adb.

## 4. הקמה ב-adb (טכנאי / בדיקות)

```bash
# טלפון מאופס; באשף מדלגים על חשבון Google; מפעילים אפשרויות מפתחים + "ניפוי באגים ב-USB"
adb install FilterPhone-universal.apk
adb shell dpm set-device-owner com.filterphone.app/.DeviceAdmin
#   Success: Device owner set to package com.filterphone.app
```
אחר כך פותחים את FilterPhone ומזינים קוד הפעלה רגיל (ממשק ← קודים ← "קוד הפעלה חדש").
הגדרות מנהל המכשיר מוחלות לבד; "VPN תמיד מופעל" ננעל ברגע שיש הגדרות VPN.

שגיאות נפוצות:
- `there are already some accounts on the device` — יש חשבון (Google / יצרן / וואטסאפ...). מוחקים
  את כל החשבונות בהגדרות, או מאפסים ומדלגים על החשבון באשף.
- `already several users` / פרופיל עבודה — מוחקים משתמשים / פרופילים נוספים.
- `device owner is already set` — הטלפון כבר מנוהל (ע"י FilterPhone או אחר): איפוס.

אחרי שהכול עובד מומלץ להפעיל `disallow_debugging` (ואז adb חסום).

## 4א. הקמה דרך Shizuku (בלי מחשב, בלי root)

לטלפון **שכבר בשימוש** (ולא כדאי לאפס אותו ל-QR) ואין בו root — אפשר להקים הכול בלחיצה אחת
דרך **Shizuku**. Shizuku מריץ שרת מקומי קטן בהרשאת **shell (uid 2000)** — בדיוק ההרשאה של
adb, רק בלי מחשב מחובר. FilterPhone מריצה דרכו את **אותן פקודות בדיוק** כמו ב-adb
(`dpm set-device-owner`, `pm grant`). זה **לא** root, לא exploit ולא מעקף — מה שאנדרואיד לא
מתיר, מדווח ככשל, כמו בכל מסלול.

> דרישות שאנדרואיד מציב להפיכת אפליקציה למנהל מכשיר **זהות** בכל המסלולים: הטלפון צריך להיות
> בלי חשבונות ובלי משתמשים/פרופילים נוספים. לרוב המשמעות שגם מסלול Shizuku מתאים בעיקר לטלפון
> נקי יחסית; אם יש חשבונות — מוחקים אותם קודם (ראו השגיאות בסעיף 4). היתרון על QR: בלי איפוס יצרן.

**הקמה חד-פעמית של Shizuku בטלפון:**
1. מתקינים את אפליקציית **Shizuku** (Google Play, או GitHub: `RikkaApps/Shizuku`).
2. מפעילים את שירות Shizuku. באנדרואיד 11 ומעלה — **בלי מחשב**, דרך "ניפוי אלחוטי":
   הגדרות ← אפשרויות מפתחים ← **ניפוי באגים אלחוטי (Wireless debugging)** ← מפעילים; ואז
   באפליקציית Shizuku לוחצים "Start" ופועלים לפי ההוראות (צימוד חד-פעמי עם קוד). באנדרואיד 10
   ומטה — מפעילים פעם אחת ממחשב: `adb shell sh /storage/emulated/0/Android/data/moe.shizuku.privileged.api/start.sh` (מופיע באפליקציה).
3. בתוך FilterPhone לוחצים **"הקמה בלחיצה אחת"**. בפעם הראשונה קופץ חלון של Shizuku לאישור —
   מאשרים ל-FilterPhone. מכאן הכול קורה לבד: מנהל מכשיר, WRITE_SECURE_SETTINGS, פטור סוללה,
   אישור VPN, התראות, ותעודה.

**מגבלה:** שירות Shizuku **נעצר באתחול** (אלא אם יש root). אחרי כל הפעלה מחדש של הטלפון צריך
להפעיל את Shizuku שוב (כמה שניות). אבל אחרי שההקמה כ-Device Owner הצליחה — **הניהול עצמו נשאר
קבוע גם בלי Shizuku**: Shizuku נחוץ רק לרגע ההקמה, לא לאכיפה השוטפת. מי שרוצה שגם ההקמה תשרוד
אתחול צריך root (מסלול `provisionRoot`) או QR על טלפון מאופס.

## 5. עדכון האפליקציה

**במנהל מכשיר** התקנת APK חסומה, ולכן FilterPhone מעדכנת את עצמה בדרך הרשמית שאנדרואיד נותן
ל-Device Owner (התקנה שקטה ב-PackageInstaller):

1. הבנייה ב-GitHub בודקת את ה-APK (`tools/apk_release.py`: לא debuggable, targetSdk, הרשאות —
   כולל שאין הרשאות פרטיות כמו הודעות / אנשי קשר / מיקום — ורכיבים) ויוצרת `FilterPhone.json`
   עם versionCode ו-SHA-256 לכל קובץ. הפרסום לשרת מעלה אותו יחד עם ה-APK.
2. השרת מציע עדכון בתשובה לדיווח התקופתי — רק אם ה-SHA-256 של הקובץ בדף ההורדה תואם לרשום.
3. הטלפון: רק גרסה חדשה יותר שמתאימה למעבד; הורדה ב-HTTPS עם גבול גודל; **SHA-256 תואם**;
   בקובץ עצמו — **אותה חבילה, אותו versionCode ואותה תעודת חתימה** (וגם אנדרואיד עצמו מסרב
   לעדכון בחתימה אחרת). ההורדה ב-Wi-Fi; בחבילת גלישה — רק אחרי 3 ימי המתנה.
4. אם המנהל חסם התקנת אפליקציות (`disallow_install_apps` — אנדרואיד חוסם בה גם את מנהל
   המכשיר), החסימה משוחררת רק לזמן ההתקנה, ומוחזרת מיד אחרי (וגם בבדיקה התקופתית).
5. כישלון: לא מתקינים, מנסים שוב אחרי שעה / 3 / 6 / 12 / 24 שעות, ומדווחים. בממשק: שורה
   "עדכון אוטומטי" בכרטיס המכשיר, ו"עדכון האפליקציה נכשל" / "האפליקציה עודכנה" ביומן הטלפון.

**בלי מנהל מכשיר** אנדרואיד לא מתיר עדכון שקט: האפליקציה מציגה "גרסה חדשה של FilterPhone"
עם כפתור לדף ההורדה, והמשתמש מתקין מעל הקיימת (ההגדרות נשמרות).

**חזרה לגרסה קודמת:** אנדרואיד לא מתקין versionCode נמוך יותר. כדי לתקן גרסה פגומה מפרסמים
בנייה חדשה (כל בנייה ב-GitHub מעלה את המספר).

## 6. FRP — הגנה אחרי איפוס יצרן

**מה זה:** אחרי איפוס שלא נעשה מתוך ההגדרות (מצב שחזור / fastboot / מחיקה מרחוק), אשף ההקמה
דורש להתחבר עם חשבון Google מורשה. בלי החשבון — הטלפון לא נפתח.

**מה FilterPhone עושה:** במנהל מכשיר, באנדרואיד 11 ומעלה, היא קובעת את החשבונות המורשים
(`setFactoryResetProtectionPolicy`) לפי `frp_accounts` בממשק. בטלפון ישן יותר — מדווח "נכשל".

**דרישות:**
- Device Owner (מכשיר מנוהל במלואו), **אנדרואיד 11+**;
- שירותי Google בטלפון (FRP הוא חלק מאשף ההקמה של גוגל — בטלפון בלי Google אין FRP);
- מזהה החשבון **המספרי** של Google (לא כתובת המייל): מתחברים לחשבון ופותחים את
  People API — `people/me` עם `personFields=metadata` — ומעתיקים את `metadata.sources[].id`
  (מספר של 21 ספרות, מהמקור מסוג PROFILE). הממשק מקבל 6–30 ספרות;
- לשמור את הגישה לחשבונות האלה. מי שאיבד אותם — לא יוכל לפתוח טלפון שאופס.

**מה FRP לא עושה — חשוב:**
- **לא מונע את האיפוס עצמו.** אף אפליקציה לא יכולה למנוע איפוס ממצב שחזור; מי שמחזיק בטלפון
  יכול תמיד למחוק אותו. FRP רק הופך את הטלפון ללא שמיש עד שמתחברים עם חשבון מורשה.
- אחרי האיפוס הכול נמחק, כולל FilterPhone והניהול. אחרי שחרור ה-FRP הטלפון "חדש" — כדי לנהל
  אותו שוב מקימים מחדש ב-QR.
- `disallow_factory_reset` חוסם רק את האיפוס מתוך ההגדרות.

**zero-touch / Samsung Knox** (הקמה אוטומטית של מכשיר מנוהל כבר מהקופסה, וגם אחרי איפוס) —
**לא מוגדר אצלנו ולא נבדק.** דורש:
- **zero-touch (Android Enterprise):** טלפונים שנקנו ממשווק מורשה, שרושם אותם (IMEI) לחשבון
  הלקוח בפורטל zero-touch; תצורה בפורטל שמגדירה את FilterPhone כ-DPC עם אותם נתונים כמו ב-QR
  (כתובת ההורדה וטביעת החתימה). צריך לאמת את התהליך מול המשווק / גוגל לפני שמבטיחים ללקוח.
- **Samsung Knox Mobile Enrollment:** טלפוני סמסונג; חשבון Knox; רישום המכשירים ע"י המשווק
  (או Knox Deployment App); פרופיל שמצביע על ה-APK בדף ההורדה.
גם עם אלה — איפוס ממצב שחזור עדיין אפשרי; ההבדל הוא שאחרי האיפוס הטלפון חוזר לניהול לבד.

## 7. הוצאת טלפון מניהול (לקוח עוזב / טלפון למכירה)

אין כרגע כפתור "שחרור ניהול" מרחוק. הדרך המסודרת:
1. בממשק, במכשיר: מכבים את "חסימת איפוס יצרן" (`disallow_factory_reset`) ומרוקנים את `frp_accounts`.
2. מחכים לסנכרון (עד 15 דקות, או פתיחת FilterPhone בטלפון ומשיכה לרענון) — בכרטיס Device Owner
   השורה מסומנת "הוחל".
3. איפוס יצרן **מתוך ההגדרות**. איפוס מההגדרות הוא "מאושר" ולא מפעיל FRP.
4. מוחקים את המכשיר בממשק (המפתח שלו מוסר מהשרת).

## 8. רשימת בדיקה על טלפון אמיתי (לפני לקוחות)

- [ ] QR בטלפון מאופס: התקנה, "מנהל מכשיר: כן", כל השורות "הוחל", המכשיר ירוק.
- [ ] כיבוי VPN מההגדרות — חסום; מצב טיסה וחזרה — המנהרה חוזרת לבד; אין אינטרנט בלי מנהרה.
- [ ] הסרת FilterPhone / איפוס מההגדרות / מצב בטוח / משתמש אורח — חסומים.
- [ ] אתחול: ה-VPN עולה לבד (גם לפני פתיחת האפליקציה), הדיווח לשרת ממשיך.
- [ ] אפליקציה חסומה מוסתרת; ביטול החסימה בממשק — חוזרת אחרי סנכרון.
- [ ] עדכון: פרסום בנייה חדשה ← בתוך ~15 דקות ב-Wi-Fi הטלפון מתעדכן, ביומן "האפליקציה עודכנה",
      ה-VPN חוזר לבד, `disallow_install_apps` (אם הופעל) חזר.
- [ ] FRP (אנדרואיד 11+, חשבון בדיקה): איפוס ממצב שחזור ← האשף דורש את החשבון.
- [ ] סמסונג ושיאומי: חיסכון בסוללה / "הפעלה אוטומטית" — ההתראה "הסינון פעיל" נשארת אחרי לילה.
